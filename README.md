# ⚡ GridGuard — Electricity Theft Detection from Smart Meter Data

**Anomaly detection on smart-meter consumption patterns to flag electricity theft / leakage — a production-grade pipeline + in-browser scoring demo built on the public SGCC benchmark (42,372 consumers × 1,034 days, 8.53% flagged theft).**

> Indian DISCOMs lose a large share of purchased power to theft and billing
> defects (aggregate technical & commercial loss). GridGuard demonstrates a
> deployable screening layer: rank consumers by theft probability so that a
> limited inspection crew is pointed at the highest-yield meters first.

## Live demo

**https://gridguard.vercel.app** — 100 real SGCC consumers scored **in your
browser** (ONNX Runtime Web, WASM): no data leaves the page, no server
inference. Includes an "analyze your own series" mode — paste daily kWh
readings, get a risk score + explanation.

## What it does

| Stage | File | What happens |
|---|---|---|
| Data | `src/data.py` | Load SGCC csv (42,372 × 1,034 daily kWh + FLAG), tidy by consumer, enforce chronological order |
| Clean | `src/features.py::impute` | Clip negative readings → linear interpolation over interior gaps → nearest-fill edges → 0 for dead meters |
| Features | `src/features.py` | 22 features per 90-day window: level (mean/std/quartiles/CV), shape (skew/kurtosis), zero-behaviour (zero-ratio, longest dead spell), temporal (weekday/weekend, month spread), drift (half-ratio, OLS slope), volatility (MAD, std-of-diff, mean abs pct change) |
| Train | `scripts/train.py` | 12 windows/consumer (10 non-overlapping + 2 end-anchored), **consumer-grouped** CV + consumer-level holdout, 3 candidate models, threshold policy (balanced + high-precision tiers), ONNX export, parity check |
| Serve | `web/` | Vite + React + ONNX Runtime Web; identical feature engine in TypeScript, asserted equal to Python bit-for-bit |
| Tests | `tests/`, `web/src/**/*.spec.ts` | 20+ pytest cases + vitest parity goldens; CI gates both |

## Why it's honest ML

- **Group-aware evaluation** — a consumer's windows never straddle train/test
  (no leakage via near-duplicate windows). CV uses `StratifiedGroupKFold`.
- **Consumer-level metrics** — operational reality: one consumer = one
  decision. We report PR-AUC, precision/recall, and **precision@top-k%**
  (inspection-budget view) on held-out consumers.
- **Imbalanced-data realism** — base rate 8.5%; we optimize PR-AUC (not
  accuracy), expose threshold trade-offs instead of hiding them.
- **Cross-language parity** — the exact feature code runs in Python (training)
  and TypeScript (browser); `tests/data/parity_cases.json` goldens are
  generated by Python and asserted in vitest.
- **Explainability** — every risk score lists which features deviate from
  honest-consumer bands (Q1–Q3) and by how much.

## Quickstart

```bash
# python side
uv venv .venv && source .venv/Scripts/activate   # or bin/activate
pip install -r requirements.txt
python scripts/prepare.py   # needs data/raw/sgcc_full.csv (see below)
python scripts/train.py
pytest -q

# web side
cd web && npm install && npm run build && npm run preview
# or: npm run dev
```

**Dataset**: Kaggle [`bensalem14/sgcc-dataset`](https://www.kaggle.com/datasets/bensalem14/sgcc-dataset)
(mirror of the State Grid Corporation of China theft-detection benchmark
published with Zheng et al., *Wide & Deep CNN, 2017*). Place
`data set.csv` → `data/raw/sgcc_full.csv`. The repo ships committed test
fixtures so the test suite runs without the 163 MB download.
